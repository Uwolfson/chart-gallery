Chart gallery

Twenty-six reusable chart recipes for survey and behavioural analysis: what moves a metric and which attributes matter, how rule-based segments split, what a segment does over time, where people flow, where sessions are lost. One small library on top of Apache ECharts — no framework, no build step.

All numbers on this page are synthetic demo data in three invented settings: a travel booking site, a survey of hotel guests and a language-learning app.

State timeline

ChartKit.stateTimeline(el, opts)

Use it to show what a segment means: one small panel per segment, a 100% bar for every time mark, colour = where people are at that moment. Panels are sorted by the outcome; the subtitle shows the outcome and the segment size.

Code
ChartKit.stateTimeline('c-timeline', {
  segments: [{ name: 'Searches by dates first', share: 25, value: 39 }, ...],   // value = outcome, optional
  marks: [0, 10, 20, ..., 120], states: ['home', 'search form', ...],
  data: { 'Searches by dates first': { home: [100, 38, ...], 'search form': [0, 54, ...] }, ... },  // % per mark, sums to 100
  colors: { home: '#0F172A', ... }, base: 27, valueLabel: 'booking rate', shareLabel: 'of visits'
});

State stack

ChartKit.stateStack(el, opts)

Use it to show where everyone is at each moment: a 100% stacked area, one layer per state, counted among the sessions that are still going on. Thin layers are hard to read in a stack, so click a layer or a chip to isolate that state — it is redrawn alone from the baseline with value labels; click the chart again to bring all states back. Marks where the base is too small are dimmed.

Code
const stack = ChartKit.stateStack('c-stack', {
  labels: ['0', '1 s', '2 s', ..., '30 min'], states: ['home', 'search form', ...],          // states: bottom to top
  data: { home: [100, 99, ...], 'search form': [0, 1, ...], ... },                      // % per mark; normalize: true rescales to 100
  colors: { home: '#334155', ... },
  base: [5000, 4980, ...], minBase: 700, lowBaseLabel: 'small base', baseLabel: 'sessions still going on:',
  onIsolate: state => console.log(state)                                                 // chips: 'my-chips' puts the buttons elsewhere
});
stack.isolate('search form');   // same as a click on the layer; stack.isolate(null) goes back; stack.dispose() removes it

Sequence index

ChartKit.sequenceIndex(el, opts)

Use it next to an aggregate chart to show the individual paths behind it: every thin strip is one session from its start to its end, colour = where the person is at that moment. Strips are grouped by outcome and sorted by duration inside a group; a red tick marks the key event. A logarithmic time axis keeps both the first seconds and the long tail readable. Hover a strip for details.

Code
const seq = ChartKit.sequenceIndex('c-sequence', {
  rows: [{ group: 'booked', end: 271, mark: 240, segments: [[0, 33, 0], [33, 60, 1], ...] }, ...],   // [from, to, index in states], seconds
  states: ['home', 'search form', ...], colors: { home: '#334155', ... },
  groups: [{ key: 'no booking', label: 'did not book' }, { key: 'booked', label: 'booked' }],
  markLabel: 'booking', scale: 'log'
});
seq.redraw({ scale: 'linear', maxTime: 600 });   // switch the time axis

Segment tree

ChartKit.segmentTree(el, opts)

Use it for segments defined by rules (a decision tree on the variables that drive the metric). Every condition is written once, on its own split; every node — including the intermediate ones — shows its size and its value. Node size = share, colour = above or below the overall value.

Code
ChartKit.segmentTree('c-tree', {
  tree: { name: 'All visits', share: 100, value: 27, children: [
    { name: 'Came from a price alert', share: 5, value: 61 },
    { name: 'Booked here before', share: 24, value: 41, children: [...] } ] },
  base: 27, valueLabel: 'booking rate', shareLabel: 'of visits'
});
// python/tree_segments.py turns a fitted sklearn tree into this nested structure

Diverging bars

ChartKit.divergingBars(el, opts)

Use it as the first chart of a step: what moves the metric up and what moves it down. Each bar is the difference in the metric with and without a factor, in percentage points; the label gives both values.

Code
ChartKit.divergingBars('c-drivers', {
  items: [{ name: 'Booked here before', withValue: 41, withoutValue: 23, share: 24 }, ...]
});

Grouped bars

ChartKit.groupedBars(el, opts)

Use it whenever two or three numbers per category have to be compared: put them side by side on one scale instead of separate panels.

Code
ChartKit.groupedBars('c-grouped', {
  names: ['Searches by dates first', ...],
  series: [{ name: 'share of visits', values: [...] }, { name: 'booking rate', values: [...] }]
});

Flow sankey

ChartKit.flowSankey(el, opts)

Use it to connect three groupings: where a visit starts, what happens, how it ends. Nodes are reordered to reduce crossings (barycenter method), similar nodes share a colour family across columns, and clicking a node can navigate to the place where that segment is explained.

Click a node.

Code
ChartKit.flowSankey('c-flow', {
  columns: [['Searches by dates first', ...], ['compared in the results list', ...], ['Decisive booker', ...]],
  links: [{ source: 'Searches by dates first', target: 'compared in the results list', value: 661 }, ...],
  colors: { 'Searches by dates first': '#2563EB', ... }, pinLast: ['Saved nothing'],
  onNodeClick: name => location.hash = '#' + slug(name)
});

Segment map

ChartKit.segmentMap(el, opts)

Use it to put every segment on one picture: x = how big, y = how good. Labels are placed automatically so they do not overlap; a leader line is drawn when a label had to move away from its point.

Code
ChartKit.segmentMap('c-map', {
  points: [{ name: 'Searches by dates first', x: 25, y: 39, group: 'first two minutes', color: '#2563EB' }, ...],
  xName: 'share of all visits, %', yName: 'booking rate, %',
  reference: { y: 27, label: 'average 27%' }, symbols: { 'first two minutes': 'circle', style: 'rect' }
});

Ladder

ChartKit.ladder(el, opts)

Use it as the spine of a report: "of 100 who started, N reached each step", with the loss and its reason written next to every rung. Rungs can link to the section that explains them.

Code
ChartKit.ladder('c-ladder', { steps: [
  { name: 'Opened the site', value: 100 },
  { name: 'Ran a search', value: 64, loss: 'left from the home page', href: '#step-1' }, ... ] });

Heat table

ChartKit.heatTable(el, opts)

Use it to describe segments by variables. A cell is shaded only when it differs noticeably from the overall value (at least 3 points and 15% relative), so the eye goes to real differences.

Code
ChartKit.heatTable('c-heat', {
  rows: ['Booked here before', ...], columns: [{ name: 'Goes straight to booking', sub: '6% of visits' }, ...],
  values: { 'Booked here before': [52, 61, ...] }, overall: { 'Booked here before': 24 }
});

Penalty–reward map

ChartKit.penaltyRewardMap(el, opts)

Use it to show what an attribute does to a choice from both sides: x = penalty (how much a badly delivered attribute pushes people away, in percentage points), y = reward (how much a well delivered one pulls them in). Dashed lines at the two means split four zones — attract (high reward, low penalty), key (both high), basic (high penalty, low reward), secondary — and the point colour is the zone. Tick the option to see the ± confidence crosshair behind each point; labels are moved apart automatically with leader lines; a zone table is rendered under the chart. Call the function several times with `highlight` and `compact` to get small multiples per group on a shared scale.

Code
ChartKit.penaltyRewardMap('c-penalty-reward-map', {
  points: [{ name: 'Value for money', x: 8.5, y: 12.4, xCi: 2.3, yCi: 1.3 }, ...],   // x = penalty, y = reward, pp; ± optional
  xName: 'penalty, pp', yName: 'reward, pp', unit: 'pp',
  zones: { topLeft: 'attract', topRight: 'key', bottomRight: 'basic', bottomLeft: 'secondary' },
  ci: true, table: true                       // table: an element / id, or true = a div right after the chart
});
// small multiples: the same call per group with compact: true, highlight: 'Pool or gym', xRange: [-1, 17], yRange: [-1, 16]

Contribution waterfall

ChartKit.contributionWaterfall(el, opts)

Use it to explain a gap: how a group gets from a reference value (the average hotel) to its own value, one horizontal step per factor. Steps are sorted by absolute size, blue raises the value and orange lowers it; a dashed bar sums all factors together and a grey bar holds the residual the factors do not explain. The start and end bars stand on zero, every step starts where the previous one ended (a transparent base stack). Hover a row for the value and its ± error.

Code
ChartKit.contributionWaterfall('c-contribution-waterfall', {
  start: { label: 'Average hotel', value: 54.0 }, end: { label: 'Hotel D, actual', value: 62.1 },
  steps: [{ name: 'Location', value: 3.8, ci: 1.0 }, { name: 'Noise insulation', value: -2.2, ci: 0.9 }, ...],   // pp, sorted by |value|
  unit: '%', stepUnit: 'pp', summaryLabel: 'All attributes together', residualLabel: 'Not explained by attributes'
});

Bar with dots

ChartKit.barWithDots(el, opts)

Use it when one number per item has to be shown together with its stability: the bar is the effect on the full base (blue raises the outcome, orange lowers it; one colour when the measure is unsigned), the dots are the same measure in each wave, light to dark. With `ci: true` a whisker shows the ± confidence interval across the bar; it is always in the tooltip. Items are sorted by absolute effect, largest on top.

Code
ChartKit.barWithDots('c-bar-with-dots', {
  items: [{ name: 'Room cleanliness', value: 8.7, ci: 1.18, waves: [8.5, 8.2, 8.5] }, ...],   // value on the full base, one entry per wave
  waveNames: ['wave 1', 'wave 2', 'wave 3'], unit: ' pp', signed: true, ci: true, baseLabel: 'all waves'
});
// an unsigned score from an older method: { ..., signed: false, reference: '#7C3AED', unit: '%' }

Rank bump

ChartKit.rankBump(el, opts)

Use it to show whether the order of items holds from wave to wave: y = rank (1 on top), one line per item across the waves. Lines that moved by `minMove` places or more (default 5) between any two waves are coloured, the rest stay grey, so the eye goes to real movement; the end label carries the net change, e.g. 'Breakfast quality (−7)'. Hover a line to focus it and read every rank.

Code
ChartKit.rankBump('c-rank-bump', {
  waves: ['wave 1', 'wave 2', 'wave 3'],
  items: [{ name: 'Room cleanliness', values: [14.3, 15.56, 16.47] }, ...],   // or ranks: [1, 1, 2] directly
  minMove: 5, color: '#7C3AED'
});

Dumbbell

ChartKit.dumbbell(el, opts)

Use it when every row has two values of the same measure to compare — before and after, in the first search and in the last, users and non-users. The two dots are the values, the thick line between them is coloured by direction (blue when the second value is higher, orange when lower), the labels at both ends give the numbers, and a short vertical dash marks a base (the overall value) per row or for the whole chart. Rows where the difference is not significant are passed with dim: true and drawn faded. Hover a row for both values, the difference and the base.

Code
ChartKit.dumbbell('c-dumbbell', {
  rows: [{ name: 'Price range', a: 52, b: 38, reference: 44 }, { name: 'Pool', a: 11, b: 10, reference: 10, dim: true }, ...],
  aLabel: 'in the first search', bLabel: 'in the last search before booking', referenceLabel: 'in all searches',
  format: v => Math.round(v) + '%', min: 0            // reference: 44 (one base for all rows) or [refA, refB] per row
});

Forest plot

ChartKit.forestPlot(el, opts)

Use it to show what a model says each factor does on its own, holding the rest constant: one row per coefficient, a point at the estimate and a whisker for the 95% interval, sorted so the largest effect is on top. The reference line is 0 for differences in percentage points, or 1 for ratios (scale: 'ratio', multipliers on a log axis). Significant rows (p below alpha, or an interval that misses the reference) get a coloured point — blue above the reference, orange below — a dark whisker and a bold label such as "+3.2 pp [1.1; 5.3]"; the rest are grey. Hover a row for the numbers and the p-value.

Code
ChartKit.forestPlot('c-forest-plot', {
  rows: [{ name: 'Studies daily', est: 21.3, lo: 15.6, hi: 27.0 }, { name: 'Aged under 35', est: -1.1, lo: -4.6, hi: 2.4, p: 0.54 }, ...],
  unit: 'pp', xName: 'change in the chance of finishing the course, pp'
});
ChartKit.forestPlot('c-forest-plot-ratio', { rows: [{ name, est: 1.71, lo: 1.38, hi: 2.12 }, ...], scale: 'ratio', nsLabel: '(n.s.)' });

Clustered heatmap

ChartKit.clusteredHeatmap(el, opts)

Use it to see which groups resemble each other in a profile of many variables — hotel types by the attributes their guests value, segments by the behaviours they show. Rows are variables, columns are groups; a cell is shaded by how far the group is from the overall value of that row (blue above, orange below, deeper = larger), or by the signed value itself when no overall is given. Rows and columns are reordered by Ward clustering and the dendrograms are drawn next to the map (rows to the right, columns below), so similar groups stand side by side. With orderBy: 'City hotel' the columns are instead sorted by their Euclidean distance to that column, the distance is written in the header and the column tree is omitted. Hover a cell for the value and the overall.

Code
ChartKit.clusteredHeatmap('c-clustered-heatmap', {
  rows: ['Room cleanliness', 'Value for money', ...], columns: ['City hotel', 'Resort', ...],
  values: [[71, 70, ...], [54, 49, ...], ...],      // one array per row, one number per column
  overall: [71, 58, ...],                            // cell = value − overall; omit to shade the signed values themselves
  cluster: { rows: true, cols: true }, unit: 'pp'    // or orderBy: 'City hotel' to sort columns by distance to one column
});

Network graph

ChartKit.networkGraph(el, opts)

Use it to show a fitted network of binary behaviours — a Bayesian network, a path model — in the "Tetrad + Gephi" style: every node is a behaviour, its size is the share of people who show it (6 + 34·sqrt(share / max)), its colour is the community found by a greedy modularity pass (or passed per node), and the label reads "Name N%". Every edge is a model coefficient: width = 1 + 9·|coef| / max, colour = the source node at 85% opacity, curved with an arrow, labelled ".23". The default layout is a deterministic Fruchterman–Reingold force layout; with layout: 'columns' the nodes are placed in the columns given by node.column (a "path to the target" view), ordered inside each column by the barycentre of their predecessors, with captions above the columns, a ring on the target node and its incoming edges drawn in the text colour. Hover a node or an edge for the numbers; drag to pan, wheel to zoom.

Code
ChartKit.networkGraph('c-network-graph', {
  nodes: [{ name: 'Signed in', prevalence: 38, column: 0 }, { name: 'Compared rooms', prevalence: 17, column: 2 }, { name: 'Booked', prevalence: 27, column: 3 }, ...],
  edges: [{ source: 'Compared rooms', target: 'Booked', coef: 0.43 }, { source: 'Entered dates', target: 'Browsed destinations', coef: -0.22 }, ...],
  target: 'Booked', layout: 'force'                      // or layout: 'columns', columns: ['How the visit started', 'First actions', 'Engagement', 'Outcome']
});

Risk map

ChartKit.riskMap(el, opts)

Use it to rank the things that go wrong on the way to an outcome: x = how common the event is (share of sessions, log scale), y = how often people leave without the outcome right after it. Bubble area = sessions lost that way, colour = stage, a hollow bubble = too few cases to trust, the whisker = 95% Wilson interval, the dashed line = the background rate after an ordinary action. Italic captions name the quadrants; the shaded zone is "common and at least twice the background". Hover a bubble for the counts.

Code
ChartKit.riskMap('c-risk-map', {
  events: [{ name: 'no rooms for these dates', note: 'sold out', category: 'search', x: 6, n: 3600, k: 1440 }, ...],   // x = % of sessions, k = lost of n
  background: 9.5, backgroundLabel: 'background, ordinary action', minN: 100,                                   // hollow bubble below minN
  colors: { start: '#334155', search: '#2563EB', ... }, labelPositions: { 'page crash': 'right' },
  quadrants: { topLeft: 'rare but deadly', topRight: 'mass killers', bottomRight: 'loud but harmless', bottomLeft: 'almost harmless' },
  zone: { x: 5, factor: 2, label: 'common and deadly' }, xName: 'share of sessions (log) →', yName: '↑ lost within a minute, %'
});

Event density

ChartKit.eventDensity(el, opts)

Use it to show when things happen after a key moment (a booking, a sign-up, a first visit): one smoothed curve per channel on a log time axis with readable ticks (30 s, 1 min, ... 24 h, or days when the ticks are passed in). Each curve is a kernel density of log time scaled to peak 1, so shapes are compared, not volumes; the tooltip gives the cumulative share of each channel by the moment under the cursor. Dashed verticals mark milestones such as "reminder e-mail". Pass raw times (the density is computed in the browser) or precomputed curves.

Code
ChartKit.eventDensity('c-event-density', {
  channels: [{ name: 'contact property (1250)', color: '#2563EB', times: [18, 6400, 2.5, ...] },      // minutes since the key moment
             { name: 'leave a review (2100)', times: [...], area: true }, ...],                // or curve: [...] + cum: [...] aligned with grid
  tMin: 0.5, tMax: 43200, ticks: [1, 5, 30, 60, 360, 1440, 4320, 10080, 43200],
  milestones: [{ t: 1, label: 'confirmation e-mail · 1 min' }, { t: 360, label: 'reminder e-mail · 6 h' }],
  xName: 'time since booking', cumLabel: 'by this moment'
});

State butterfly

ChartKit.stateButterfly(el, opts)

Use it when the "gone" mass matters as much as the active one: a 100% stacked area over time mirrored around zero — states that mean left or paused grow upwards, active screens sit below the line, the y axis runs 0–100 both ways. Time marks (log or linear) are passed in as labels. Click a legend item to toggle that state; hover for the exact shares at a mark.

Code
ChartKit.stateButterfly('c-state-butterfly', {
  labels: ['0', '1 s', '2 s', ..., '2 h'], states: ['home', 'search form', ..., 'paused', 'left without booking', 'left with booking'],
  up: ['paused', 'left without booking', 'left with booking'],                 // drawn above zero; the rest below
  data: { home: [100, 99, ...], 'left with booking': [0, 0, ...], ... },         // % of ALL sessions per mark
  colors: { home: '#334155', ... }, yName: '← active on the site        left or paused →'
});

Segmentation panel

ChartKit.segmentationPanel(el, opts)

Use it as the first table after a segmentation: one row per segment with its name, a share-of-base bar, the outcome bar with its value and a sparkline of the state timeline — a tiny 100% stacked column per time mark, colour = state. Rows are sorted by the outcome, the overall row stays on top, so the eye reads "who is big, who converts, what they do" in one pass. Hover a sparkline column for the share of a state at that mark. Plain HTML, sizes itself; needs lib/parts/segmentation-panel.css.

Code
ChartKit.segmentationPanel('c-segmentation-panel', {
  rows: [{ name: 'Searches by dates first', share: 25, value: 39, color: '#2563EB' }, ..., { name: 'All visits', share: 100, value: 27, overall: true }],
  valueLabel: 'booking rate', shareLabel: 'share of visits',
  mini: { marks: [0, 10, ..., 120], states: ['home', 'search form', ...], colors: { home: '#0F172A', ... },
          data: { 'Searches by dates first': { home: [100, 38, ...], 'search form': [0, 54, ...] }, ... }, unit: 's', label: 'screen at' }   // optional sparkline
});

Session anatomy

ChartKit.sessionAnatomy(el, opts)

Use it to show one session as a story: a shared time axis (linear or log; pauses longer than `pauseAfter` are hatched and shortened), lanes = screens as coloured segments with a tick at every transition, a row of selection actions — what was added to a shortlist or a trip (numbered dot = new item, small dot = one more of an item, red cross = removed), a query row (diamond at the query start, red when nothing was found, a bar while the results stayed on screen), small diamonds where a card was opened, dashed highlight window, event pins and an optional step-line value track (balance, trip total) on top. Hover any mark for a native tooltip. Controls are the caller's job: `redraw({ scale: 'log' })`, `redraw({ compressPauses: false })`.

Code
const s = ChartKit.sessionAnatomy('c-session-anatomy', {
  lanes: ['home', 'search form', 'results list', 'hotel page', 'room choice', 'booking form'],   // top to bottom
  segments: [[0, 11, 0], [11, 38, 1], [38, 97, 2], ...],                       // [from s, to s, lane index]
  end: 934, scale: 'linear', compressPauses: true, pauseAfter: 120,
  adds: [{ t: 221, n: 1, name: 'studio by the beach, 2 nights', note: 'from the room list' }, { t: 392, name: 'old town guesthouse' }],   // no n = one more of an item
  removes: [{ t: 790, name: 'studio by the beach, 2 nights' }], cards: [{ t: 99, name: 'guesthouse by the pier' }],
  queries: [{ t: 13, text: 'seaside town', found: 86, until: 97 }, { t: 232, text: 'old twon', found: 0 }],
  events: [{ t: 929, label: 'booked 211.00', color: '#059669' }], highlight: { from: 0, to: 120, label: 'first two minutes' },
  valueTrack: [{ t: 221, v: 234 }, ...], valueLabel: 'trip total',             // optional step line on top
  words: { items: 'stays in the trip', queries: 'destination searches', added: 'added stay', plusOne: 'one more night' }   // row captions and tooltip words
});
s.redraw({ scale: 'log' });   // s.redraw({ compressPauses: false }); s.dispose()

Transition graph

ChartKit.transitionGraph(el, opts)

Use it to show where people go from each screen. Nodes sit where you put them (a fixed layout keeps the picture stable between groups), node size ~ square root of entries, the label gives entries, median dwell and the share of exits that end the session there; directed edges are coloured by source, width ~ square root of the count, labelled with the share of exits from the source, and hidden below `minShare`. Links to a target that is not a node count as terminal exits. `matrix: true` adds the full from → to table under the chart, shaded blue; with `links2` and `matrixMode: 'diff'` the table shows the difference between two groups in percentage points (blue = more in the first group, orange = less).

Code
const tg = ChartKit.transitionGraph('c-transition-graph', {
  nodes: [{ name: 'home', x: 80, y: 330, entries: 24000, dwell: 9, color: '#334155' }, { name: 'search form', x: 360, y: 110, entries: 17800, dwell: 24 }, ...],
  links: [{ source: 'home', target: 'search form', count: 9347 }, { source: 'booking form', target: 'left with booking', count: 1988 }, ...],  // unknown target = exit
  links2: [...same shape for a second group...], goodEnds: ['left with booking'],
  minShare: 15, matrix: true, matrixMode: 'links'   // 'links2' | 'diff' (links minus links2, pp)
});
tg.redraw({ links: BOOKED, minShare: 25 });   // chips / switches are the caller's job; tg.dispose()

Semantic map

ChartKit.semanticMap(el, opts)

Use it to explore a 2-D embedding (t-SNE, UMAP) of texts or items: every point is one unit, coloured when it belongs to one of the top groups, grey when it belongs to another group, a ring when it has no group. A glow sits under the top groups. Zoom with the wheel after a click on the map (or with Ctrl), drag to pan, double click or use the + / − / reset buttons. Labels change with zoom: group names and their top words at low zoom, subgroups at mid zoom, small clusters at high zoom; label boxes avoid each other and point to their centroid with a leader line. Hover a point or a label for a tooltip; the group chips focus one group (hover = preview, click = pin). `onClick(point, label)` gets the point or the label that was clicked.

Code
const map = ChartKit.semanticMap('c-semantic-map', {
  points: [{ x: -3.2, y: 1.7, group: 'price', sub: 'too expensive', cluster: 'too expensive / 1', text: '...' }, ...],   // group: null = unlabelled
  levels: [{ zoom: 1, field: 'group' }, { zoom: 2.2, field: 'sub' }, { zoom: 5, field: 'cluster' }],
  words: { group: { price: ['expensive', 'fee', 'deal'] }, sub: { 'too expensive': ['expensive', 'price', 'overpriced'] }, cluster: { ... } },
  maxGroups: 8, colors: { price: '#F97316' },      // top groups get colours, the rest are grey
  onClick: (point, label) => { ... }              // one of the two is set
});
map.focus('price'); map.reset(); map.redraw({ points: NEW }); map.dispose();

Coverage chart

ChartKit.coverageChart(el, opts)

Use it to show how far a set of items (tags, rules, features) reaches into the base and where adding more stops paying: one column per item in greedy order, grey = already covered by the items before it, blue = newly covered by this one, "+N" on top, the y axis in percent of the base. Columns after the last item that adds at least `minGain` of the base sit behind a dashed line — that is the plateau. Pass precomputed `{ items, covered, added }` or raw `sets: { item: [ids] }` and let the greedy order be computed. `onClick(item)` fires on a column or its label.

Code
ChartKit.coverageChart('c-coverage-chart', {
  sets: { 'general praise': [1, 4, 9, ...], 'price': [4, 12, ...], ... },            // raw memberships: greedy order is computed here
  total: 1500, minGain: 0.005,                                                       // or precomputed: items: [...], covered: [483, 671, ...], added: [483, 188, ...]
  coveredLabel: 'already covered by earlier tags', addedLabel: 'newly covered by this tag',
  onClick: item => console.log(item)
});
ChartKit.greedyCoverage(sets, total)   // -> { items, covered, added, total } if you need the order alone
